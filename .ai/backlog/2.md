# Epic: Multi-Provider & Advanced Protocol Support (Complete)

**Ordering note (2025-08-11, updated):** ACP v2 is **deferred** — the schema is only `2.0.0-alpha.2` and still changing (provider management `providers/list|set|disable` lives in the UNSTABLE surface). Multi-provider configuration lands first, designed around the provider concept; the config/abstraction side is built now so it can map to the stabilized v2 `providers/*` methods later.

## Summary

Extend the server beyond the single OpenAI-compatible adapter: support multiple
providers (Anthropic first), provider/model configuration, and per-session
multi-LLM selection (likely via ACP v2's Partner concept). Session persistence
if needed.

## Status

- **Priority:** P1
- **Progress:** 100%
- **Completed:** 2025-08-11 — multi-provider config (F1) + Anthropic adapter (F2) merged, live-verified. Deferred items carried to Epic 3.

- **Use cases:** route turns to Anthropic (Messages API) alongside OpenAI-compatible providers
- **Requirements:** `provider/anthropic.zig` behind the adapter interface; streaming + tool calling parity with the OpenAI adapter; `ANTHROPIC_API_KEY`/`ANTHROPIC_URL` env
- **Dependencies:** Epic 1 (adapter interface, transport)
- **Verification:** mock Messages API tests; live smoke test
- **Tasks:**
  - [x] `feature/anthropic-adapter` — Anthropic Messages implementation (done — merged; live DeepSeek /anthropic verified)

### Feature: Multi-provider configuration (P1 — FIRST)
- **Use cases:** declare several named providers (base URL, key, model, effort) and select one without code changes
- **Requirements:** config file (decide format at planning) with a `providers` section; provider registry; graceful validation; a default provider + selection mechanism; design the abstraction to map to the stabilized v2 `providers/*` methods later
- **Dependencies:** Epic 1 F4 (env config pattern)
- **Verification:** config fixture tests; startup validation errors; selection tests
- **Tasks:**
  - [x] `feature/multi-provider-config` — config format + provider registry + selection (done — merged; session model config included)
