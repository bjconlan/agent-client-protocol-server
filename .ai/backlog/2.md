# Epic: Multi-Provider & Advanced Protocol Support (Future)

## Summary

Extend the server beyond the single OpenAI-compatible adapter: support multiple
providers (Anthropic first), provider/model configuration, and per-session
multi-LLM selection (likely via ACP v2's Partner concept). Session persistence
if needed.

## Status

- **Priority:** P2
- **Progress:** 0%

## Features

### Feature: Anthropic API adapter
- **Use cases:** route turns to Anthropic (Messages API) alongside OpenAI-compatible providers
- **Requirements:** `provider/anthropic.zig` behind the adapter interface; streaming + tool calling parity with the OpenAI adapter; `ANTHROPIC_API_KEY`/`ANTHROPIC_URL` env
- **Dependencies:** Epic 1 (adapter interface, transport)
- **Verification:** mock Messages API tests; live smoke test
- **Tasks:**
  - [ ] `feature/anthropic-adapter` — Anthropic Messages implementation (backlog)

### Feature: Multi-provider configuration
- **Use cases:** declare several providers (base URL, key, default model) without code changes
- **Requirements:** config file or extended env (decide at planning: TOML in `~/.config` vs env blocks); provider registry; graceful key/URL validation
- **Dependencies:** Epic 1 F4 (env config pattern)
- **Verification:** config fixture tests; startup validation errors
- **Tasks:**
  - [ ] `feature/multi-provider-config` — config format + provider registry (backlog)

### Feature: Multiple LLMs per session
- **Use cases:** a session selects/switches provider+model per turn or per partner
- **Requirements:** map to ACP mechanism — v2 `Partner` is the natural fit (client-selectable agent identities); evaluate v1 `session/config` options as interim; session-scoped provider state
- **Dependencies:** ACP v2 support feature; multi-provider config
- **Verification:** transcript test switching partners mid-session
- **Tasks:**
  - [ ] `feature/multi-llm-per-session` — partner/session provider selection (backlog)

### Feature: ACP v2 support
- **Use cases:** serve v2 clients alongside v1 (version negotiation already designed)
- **Requirements:** v2 method registry (`protocol/methods/v2.zig`); v2 types (plan content, MCP capabilities, resource links, diffs); `protocolVersion` routing end-to-end
- **Dependencies:** Epic 1 F2 (negotiation seam)
- **Verification:** v1 and v2 client transcripts both pass
- **Tasks:**
  - [ ] `feature/acp-v2` — v2 schema types + method handlers (backlog)

### Feature: Session persistence (if needed)
- **Use cases:** surviving server restarts / multi-process access
- **Requirements:** decide scope at planning — file-based snapshots vs DB; only if a real need appears
- **Dependencies:** F3 lifecycle
- **Verification:** TBD
- **Tasks:**
  - [ ] `feature/session-persistence` — persistence design + implementation (backlog)
